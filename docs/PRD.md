## 2. 背景与目标

### 2.1 产品背景

- **品牌**：智翼云工  
- **产品**：AI 助残增长服务平台  
- **价值主张**：
  - 把残保金支出变成企业增长生产力
  - 综合成本优化约 65%–70%
  - 合同 / 社保 / 薪税四流合一合规
  - 真实岗位与真实交付

**核心业务闭环**：

```
企业残保金预算 → AI 培训残障人才 → AI 数字岗位配置 → 真实工作交付 → 企业增长 + 残障就业价值
```

强调：**可交付、可追溯、可复制**。系统目标：**能签单、能派活、能交活、能对账、四流能留痕**；任务完成后可追查，能看到任务做的内容。

### 2.2 三条产品线与本期边界

| 产品线 | 内容 | 本期 |
|--------|------|------|
| 合规版 | 残保金优化、四流合一、平台运营 | **做** |
| 增长版 | AI 数字团队（内容编排、商品上架、市场调研等）可量化交付 | **仅做 1 种可量化 AI 数字岗位**；其余第二期 |
| ESG 版 | 残障就业项目、品牌公益名片 | **不做**（第二期） |

### 2.3 目标客群

- 制造、电商/外贸、品牌连锁、中大型服务企业
- 尤其：**百人以上、人力成本高** 的企业

### 2.4 收费模型（业务侧，系统需支撑记账）

| 费用类型 | 说明 |
|----------|------|
| 平台服务费 | 按企业方案收取的月/年服务费 |
| AI 工具费 | 岗位相关 AI 能力使用费（本期可并入岗位运营或单独列项） |
| 岗位运营费 | 按岗位编制 / 交付量结算 |
| 增值服务费 | 培训加急、额外质检、定制报表等 |

### 2.5 业务目标（第一期）

1. 完成自建运营后台 + 执行端任务流 + 企业只读门户的最小闭环。  
2. 支撑「合规交付 + 1 种可量化 AI 数字岗位」从签约到对账全链路。  
3. 任务全生命周期可追溯：状态、交付内容、质检意见、操作日志可查。  
4. 四流（合同、社保、发薪、个税/发票）按人按月归档并核对。  
5. 支撑首单试跑：签单 → 派活 → 交活 → 对账 → 开票回款。

### 2.6 MVP 成功标准（可验收）

| # | 成功标准 | 验收方式 |
|---|----------|----------|
| S1 | 运营可完成：建企业 → 建方案 → 配岗位 → 上人才 → 派任务 → 质检验收 → 出月账单 | 走通 1 条端到端用例 |
| S2 | 执行端仅见本人任务，可领取/提交/返工再提；提交后交付物可回看 | 角色权限用例 + 任务详情截图 |
| S3 | 企业客户只读本企业岗位、任务、台账、账单；不可见他企数据 | 跨企业隔离用例 |
| S4 | 任意已验收任务可打开追溯时间线，看到节点、交付内容、质检意见、操作日志 | 抽检 ≥10 条任务 |
| S5 | 合规台账支持按人/按月上传四流附件并标记核对状态 | 样例企业 1 个月完整台账 |
| S6 | 月账单含岗位费 + 平台服务费 + 增减项，支持开票/回款状态 | 生成并核对 1 份月账单 |
| S7 | 审计日志保留关键写操作，支持按对象追溯「谁何时改了什么」 | 改字段后日志可查 |

## 3. 范围（In / Out）

### 3.1 In Scope（第一期做）

1. **自建后台**（Web）：运营管理端 + 企业只读门户 + 执行端任务界面（可为同一 Web 按角色分流）。  
2. **企业与方案管理**：签约信息、残保金基数/缺口、月服务费、方案版本与起止日。  
3. **岗位配置**：本期仅支持 **1 种可量化 AI 数字岗位类型**（具体岗位类型见待决问题 Q1，默认候选：内容编排 / 商品信息整理 / 市场调研整理 三选一）。  
4. **人才与培训**：残障人才档案、培训进度、上岗绑定。  
5. **任务与交付 + 追溯时间线**（核心）：派活、领取、提交、质检、返工、验收；交付内容（文字 + 附件/链接）；操作日志。  
6. **合规台账四流**：合同、社保、发薪、个税/发票按人按月归档与核对。  
7. **对账结算**：月账单、开票状态、回款状态。  
8. **权限隔离**：运营 / 企业客户 / 执行端。  
9. **附件存储与基础审计日志**。

### 3.2 Out of Scope（第一期明确不做）

| 不做项 | 说明 |
|--------|------|
| 增长版全量 AI 工具 | 不做内容编排/上架/调研等多工具矩阵，仅 1 种岗位类型 |
| ESG 素材库 / 公益名片 | 第二期 |
| 飞书/Notion/表格拼凑业务主系统 | 仅允许临时导入导出，不以飞书为运行时 |
| 自动对接社保局/税局申报 | 本期人工上传归档，不做官方接口申报 |
| 复杂财务总账 / ERP | 只做到账单、开票、回款状态 |
| App 原生客户端 | 本期 Web 响应式即可 |
| 多租户白标 / 开放 API 给第三方 | 第二期再评估 |
| AI 自动质检替代人工 | 本期质检以人工规则+勾选为主，AI 辅助可选后续 |

## 4. 用户角色与权限

### 4.1 角色定义

| 角色 | 说明 | 数据范围 |
|------|------|----------|
| 运营（Platform Ops） | 平台内部运营/交付/财务协助 | 全平台读写（业务数据全开） |
| 企业客户（Enterprise） | 签约企业侧对接人 | **只读**本企业：岗位、任务、台账、账单 |
| 执行端（Worker） | 残障人才 / 交付执行人 | **仅自己的任务**（读自己档案只读字段；写任务流转） |

> 本期不做细粒度「企业多角色」（如企业财务/企业 HR 分权）；企业侧统一为只读账号。运营侧不做部门级分权。

### 4.2 权限矩阵（MVP）

| 模块 / 能力 | 运营 | 企业客户 | 执行端 |
|-------------|------|----------|--------|
| 企业与方案 CRUD | ✓ | 只读本企业方案 | ✗ |
| 岗位配置 CRUD | ✓ | 只读本企业岗位 | ✗ |
| 人才档案 CRUD | ✓ | ✗（可见在岗本企业人员脱敏列表可选，默认不做） | 只读本人基础信息 |
| 派任务 / 改派 | ✓ | ✗ | ✗ |
| 领取 / 提交 / 返工提交 | ✓（可代操作） | ✗ | ✓ 本人任务 |
| 质检 / 验收 | ✓ | ✗ | ✗ |
| 查看任务追溯与交付物 | ✓ 全量 | ✓ 本企业任务只读 | ✓ 本人任务 |
| 合规台账上传/核对 | ✓ | 只读本企业 | ✗ |
| 账单生成与开票回款 | ✓ | 只读本企业账单 | ✗ |
| 用户账号管理 | ✓ | ✗ | ✗ |

### 4.3 鉴权要求

- 登录：账号密码（MVP）；支持运营重置密码。  
- 会话：服务端会话或 JWT，过期强制重登。  
- 所有列表/详情接口必须按角色做 **服务端数据隔离**（禁止仅前端隐藏）。  
- 企业客户、执行端禁止通过改 URL/ID 越权访问他企或他人任务（返回 403）。

**验收**：任务详情页必须同时展示——当前状态、追溯时间线、当前/历史交付物、质检意见、操作日志（按权限过滤）。

## 8. 任务追溯详细需求

### 8.1 状态机

| 状态码 | 中文 | 说明 |
|--------|------|------|
| draft | 草稿 | 运营未派发（可选，MVP 可创建即 assigned） |
| assigned | 已派发 | 待执行人领取 |
| in_progress | 进行中 | 已领取未提交 |
| submitted | 已提交 | 待质检 |
| rework | 返工中 | 质检不通过，待重新提交 |
| qa_passed | 质检通过 | 待终验（若质检=终验可合并） |
| accepted | 已验收 | 终态（成功） |
| cancelled | 已取消 | 终态 |

**推荐简化（MVP 可合并）**：

```
assigned → in_progress → submitted → (rework → submitted)* → accepted
                ↘ cancelled
```

质检不通过：`submitted → rework`；重新提交：`rework → submitted`；验收通过：`submitted → accepted`（运营一键「质检并验收」可一步到位，但日志须拆成两条或一条含两动作说明）。

### 8.2 合法流转（验收表）

| 从 | 到 | 操作者 | 条件 |
|----|----|--------|------|
| assigned | in_progress | 执行端/运营代领 | — |
| in_progress | submitted | 执行端/运营 | 交付物校验通过 |
| submitted | rework | 运营 | 质检意见必填 |
| rework | submitted | 执行端/运营 | 新版本交付物 |
| submitted | accepted | 运营 | 质检通过意见可选 |
| *非终态 | cancelled | 运营 | 备注必填 |
| accepted/cancelled | * | — | 禁止回退（需运营「复制为新任务」） |

### 8.3 时间线节点要求

每个节点至少包含：`时间、操作者、动作、从→到状态、评论/意见、关联交付版本号`。  
提交节点必须能点开查看该版本交付内容。

### 8.4 日志字段（最小集）

见 §6.4.3。额外要求：

- 所有状态变更 **必须写日志**（系统自动）。  
- 运营编辑任务标题/截止时间/改派 **必须写 changed_fields**。  
- 日志 **只追加不删改**。

### 8.5 交付物类型

| 类型 | 约束 |
|------|------|
| 文字说明 | 必填，建议 20–5000 字（上限可配置） |
| 附件 | pdf/doc/docx/xls/xlsx/png/jpg/zip 等；单文件 ≤50MB；数量 ≤20 |
| 链接 | http/https；≤20 条 |

### 8.6 企业可见范围（再强调）

| 内容 | 企业可见 |
|------|----------|
| 任务状态与时间线 | ✓ 本企业 |
| 交付说明/附件/链接 | ✓ |
| 质检结论与意见 | ✓ |
| internal 运营备注日志 | ✗ |
| 执行人残疾证完整信息 | ✗（可显示姓名） |

## 10. 非功能需求

### 10.1 权限隔离

- 服务端强制 RBAC + 行级数据隔离。  
- 所有写操作鉴权；越权返回 403，并记安全日志。

### 10.2 附件存储

- 对象存储（或等价）；私有读，经鉴权签发短时 URL。  
- 病毒扫描可第二期；本期至少限制类型与大小。  
- 删除附件：软删除，任务已验收后默认禁止物理删。

### 10.3 审计日志保留

- 任务操作日志、登录日志、关键数据变更日志保留 **≥ 24 个月**（可配置）。  
- 日志不可被业务角色删除。

### 10.4 基础可用性

- Web 主流浏览器近两个大版本（Chrome / Edge / Safari）。  
- 列表分页默认 20；关键接口 P95 < 1s（百级租户数据量）。  
- 日备份；RPO ≤ 24h（MVP 可接受）。  
- 可用性目标：工作日 9:00–21:00（上海时区）可维护窗口外尽量可用。

### 10.5 合规与隐私

- 残疾证号、手机号等敏感字段加密存储或脱敏展示。  
- 企业门户不展示与履约无关的敏感身份细节。
